# Tada Words 0.8.1 resumable canonical Family Sync

- Build: `2026072801`
- Risk tier: R4
- Issue / PR: `#145` / `#148`
- Distribution: Internal TestFlight only

This candidate makes an already parent-authorized canonical publication
crash-safe in the running product. If CloudKit fails after the durable recovery
marker is written, launch or Sync Now resumes only when the source installation,
exact Profile UUID set, record count, and complete record-set fingerprint still
match the authorized snapshot. A mismatch remains fail closed and ordinary
sync cannot publish around the marker.

Once CloudKit verifies and activates the immutable generation, the source
journal is acknowledged and every updated receiving device adopts that
generation before any ordinary upload. First-run Find Profile retains its
existing explicit iCloud account-confirmation boundary before adoption.

The approved recovery source remains Darren’s reading iPad (3). Its verified
pre-recovery backup remains the rollback boundary. Live diagnostics after the
interrupted 0.7.51 attempt showed two exact Profile UUIDs and a pending
262-record fingerprint; the new candidate must preserve that exact live
snapshot rather than reverting to the earlier 220-record observation. No
other device may publish a replacement generation.

Production recovery also requires CloudKit to accept the legacy-zone
all-records query. The prior candidate constructed that query with a
value-based predicate, which Production rejected as `BAD_REQUEST`. This
candidate uses CloudKit's supported `TRUEPREDICATE` format expression for both
stale-record discovery and post-projection verification. The Production
`TadaFamilyItem.recordName` Queryable index is deployed as a non-destructive
diagnostic and operations prerequisite.
