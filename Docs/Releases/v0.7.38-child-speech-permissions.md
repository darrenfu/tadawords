# Tada Words v0.7.38 — contextual Read permissions

**Version:** `0.7.38`

**Build:** `2026072412`

**Batch:** `child-speech-permissions-v0.7.38`

**Issue:** [#125](https://github.com/darrenfu/tadawords/issues/125)

## What changed

- The first microphone tap in Read Practice requests only still-undetermined
  Speech Recognition and Microphone permissions, in that deterministic order.
- If both permissions become authorized, the original tap continues directly
  into recording without a second tap.
- Already-authorized sessions start normally. Denied, restricted, and revoked
  access is not re-requested and retains Ask a Parent / Settings recovery.
- One in-flight request sequence prevents overlapping prompts. Navigation,
  pause, and background cancellation cannot start a stale recording or advance
  to the second prompt after cancellation.
- Guardian copy, usage descriptions, privacy disclosures, the permission
  inventory, and App Store reviewer guidance now describe the child-initiated
  prompt accurately.

## Exact-HEAD acceptance

Automated source, unit, simulator, signing, and device evidence must name the
unchanged final PR HEAD. Preserve existing app data: do not uninstall, reset
privacy state, or replace learning records.

On one physical iPhone and one physical iPad, verify separately:

1. First-install-equivalent LocalQA state requests Speech Recognition and then
   Microphone from the first Read microphone tap and continues the same tap into
   recording when both are allowed.
2. Each partial-authorization state requests only the remaining undetermined
   permission.
3. Denied, restricted, and revoked access shows Ask a Parent / Settings
   recovery without another prompt or counted learning attempt.
4. Already-authorized access records without new permission UI.
5. Rapid repeated taps, navigation away, app backgrounding, and relaunch do not
   overlap prompts or start a stale recording.

Any destructive permission reset must use an isolated LocalQA plan and separate
test state; it must not uninstall or reset the user's existing app data.
